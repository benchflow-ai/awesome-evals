# Notes — "44% vs 85%: your first cross-agent eval measures your eval harness, not the model"

**Author:** Coder Eval Team (UiPath) · **URL:** https://coder-eval.com/blog/cross-agent-eval-measures-your-eval-harness · **Type:** eng-blog · **Found:** true

## Summary (3-6 sentences)
A team ran Codex and Claude Code over the same 417 coding tasks and got 44.1% vs 85.3% — a 41-point gap that reads as a verdict on model capability. Before publishing it they hand-audited 227 of the 228 failures with no sampling, requiring every label to cite a mechanism from the run record, and sorted each failure into one of four buckets: harness-unfair (144, 63%), ambiguous (49, 22%), genuine (25, 11%), strict-criteria (9, 4%). Only 11% of failures were the model; roughly 89% sat outside its control, and the largest single cause was one flaky file-edit backend accounting for 106 of 228 failures. The post then does the thing most harness-confounding write-ups skip — it fixes the harness and re-runs, moving Codex from 44% to 76% against 82% for Claude Code. The generalizable output is the "inverse law of gap size" (the bigger a per-skill gap, the less likely it is real, because infrastructure failures are binary and total while capability differences are graded) plus a pre-flight checklist and a `pre_run` task field that aborts a task with ERROR when the grader's own preconditions fail, instead of scoring it as an agent failure.

## Key points (5-12 substantive bullets)
- **The measurement, and the audit behind it:** 417 tasks, Codex 44.1%, Claude Code 85.3%. 227 of 228 failures were audited individually (seven sub-agents in parallel, one instruction each), explicitly **no sampling**; the 228th errored out without producing an auditable verdict.
- **Attribution taxonomy that transfers to any suite:** harness-unfair 144 (63%) · ambiguous 49 (22%) · genuine 25 (11%) · strict-criteria 9 (4%). The ambiguous bucket was not slop — it was a single cluster of 30 tasks failing downstream of one broken tool, which on reclassification puts ~89% of all failures outside the model's control.
- **The score ladder makes the range explicit rather than picking a number:** 44% as measured → 81% crediting harness-unfair and strict-criteria failures → 88% adding the ambiguous cluster → 94% counting genuine failures only, against Claude Code's 85%. The authors settle on 80–88% as defensible, i.e. indistinguishable from Claude Code.
- **One dependency caused nearly half the suite to fail:** Codex's only file-create/edit tool was a single API-backed operation whose endpoint was erroring, and sandbox policy forbade a shell fallback — 106 of 228 failures. Their stated design lesson is that mapping every file mutation onto one backend call makes it a single point of failure for the whole eval.
- **Two of the eight mechanisms are eval-design bugs, not infrastructure:** an activation check (`skill_triggered`) that recognized only Claude Code's explicit `Skill` call, failing 30 tasks for Codex regardless of behavior; and a command check (`command_executed`) that regexed command *text*, so quote-escaping, a literal ID where the agent used a variable, or a different flag order all read as "never ran it."
- **Why small wiring errors become forty-point gaps:** a task verdict is a strict AND over gating criteria, so a ten-criterion task with nine passes and one unfair failure scores zero — "a single miswired check appearing across a hundred tasks costs you a hundred tasks, not a hundred criteria." Their escape hatch is `weight: 0` to demote a suspect criterion to informational rather than delete it.
- **The inverse law of gap size**, with the per-skill table behind it: Testing 100pt and Review 100pt entirely harness, Diagnostics 91pt and Data layer 65pt almost entirely harness — while the *smallest* gap, Authorization at 10pt, held the 7 genuine failures. The generating process explains it: capability differences are graded and modest, infrastructure failures are binary and total.
- **The genuine residual is specific and small,** and only visible once the noise is removed: given a query returning no rows, Codex piped the empty variable onward and got a 500; Claude Code noticed and broadened the query. The authors call this weaker adaptive persistence across a multi-step chain, not "worse at authorization."
- **The self-implicating detail:** the grader's own verification commands failed inside the same broken session and reported that as the agent's failure. The fix is a first-class `pre_run` block that runs the grader's commands before the agent starts and aborts with `FinalStatus.ERROR` and `iterations=0`, keeping a broken environment out of the pass-rate denominator entirely.
- **They name their own bias and guard it:** attribution is a judgment call whose incentive runs toward charity, so every label had to cite a run-record mechanism, the tell was mechanical (did the tool install?) rather than interpretive, and the 22% they could not decide stayed ambiguous rather than being distributed to taste. An independent check on the 125 failures reachable through the shell alone reproduces the same ordering, leaving a genuine core of 15–18 tasks out of 417.
- **Falsifiable claim offered to the reader:** rank your per-skill gaps, pull run records for the three largest and three smallest, and you should find more infrastructure in the large ones. The stronger version costs one re-run after fixing what the pre-flight flags — which is what the authors did on themselves, 44% → 76% against 82%.

## What it adds / why it's good
§3 has the thesis that the harness dominates the model from several angles — Lee's argument, Brand's AlgoTune case of "same model, different harness, opposite ranking," Hodgson's teardown of Claude Code's harness, Anthropic's VirBench showing deterministic tooling collapsing a 16.9%–91.3% spread. What it has not had is a practitioner failure census: someone reporting the number they nearly published, then showing the itemized work that made it wrong. This supplies that — a per-failure audit with counts (144/49/25/9), named mechanisms, a bounded range instead of a single corrected figure, and a re-run that closes the loop. Two things make it more than a war story. The inverse law of gap size is a genuinely reusable heuristic with a mechanical justification and a decisive test attached (did this agent's tooling install for this skill?), and it runs against intuition in a useful direction: it tells you to distrust your most impressive-looking result. And the `pre_run` / `iterations=0` design is a concrete answer to the confound rather than an observation about it — the failing environment becomes an ERROR outside the denominator instead of a low score inside it. The self-critical framing is the credibility move: the numbers here indict the authors' own eval harness, they publish the 22% they could not adjudicate rather than allocating it, and they state plainly that a 227-failure hand-audit does not scale and is a one-time instrument. ⚠️ Single suite, two agents, one organization, and the suite was an early version of what is now public — the taxonomy and the heuristic travel further than the specific percentages, which should not be read as a general Codex-vs-Claude-Code result.
